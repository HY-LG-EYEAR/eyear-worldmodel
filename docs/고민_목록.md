## B. 내가 더 고민할 것

| # | 내용 | 메모 |
|---|---|---|
| B1 | **방을 옮긴 사람 이어 붙이기** | A가 방1을 나가 거실에 얼굴 없이 잡히면 지금은 익명으로 따로 생김. "직전에 나간 사람이 1명뿐이면 같은 사람" 같은 규칙? 틀리면 다른 사람을 A로 오인 |
| B2 | **시뮬레이터 2.0 전환** | sim이 Node 메시지를 흉내 내고 → 허브 → 엔진 → 2.0 스냅샷. Node 없이 정빈과 연동 시험 가능 |
| B3 | **MQTT·HTTP 실제 연결** | 허브(`worldmodel/hub.py`)는 준비됨. paho-mqtt 구독 → `hub.submit()`, sink에 HTTP POST 붙이기 |
| B4 | 여러 Node 사이 순서 | 방마다 순서는 지키지만 방끼리는 도착 순서. 사람이 방을 옮기는 순간 잠깐 두 방에 보일 수 있음 |
| B5 | 줄 크기·tick 주기 | 지금 방마다 20개, 0.2초. 실제 Node 주기 보고 조정 |
| B6 | 방 하나에 Node 여러 대 | 지금 설정이 막고 있음 (방 1개 = Node 1대). 거실이 넓으면 필요할 수 있음 |
| B7 | 상태 확인 화면 | `hub.stats()`로 방별 수신·버림·오류 수를 볼 수 있음. 시연 때 띄울지 |
| B8 | 엔진 재시작 시 기억 | 지금은 재시작하면 전부 잊음 (구성원 30분 기억도 사라짐). 저장할지. A8 답에 따라 세션·revision 저장도 필요 |
| B9 | **기기 결과 이벤트 전달** | 협의안 10장은 `command_id`와 새 revision을 중앙에 전달하라고 함. 지금 엔진은 기기 상태만 갱신하고 전달 경로가 없음 |
| B10 | 수신 참조 구현 보강 | 협의안과 차이: 세션 등록 때 `clock_mode`를 받지 않고(2장), `can_issue`가 수동 잠금·사용자 제한을 확인하지 않음(6장) |
