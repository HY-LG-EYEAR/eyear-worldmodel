# WorldSnapshot 2.0 구현 후 확인 요청

이효창 → 송정빈 · 2026-11-14 작성, 2026-11-18 계약 2.0 협의안(2026-11-13 PDF)과 대조해 수정

2.0 협의안대로 World Model 엔진을 구현했고, 문서 예제는 Schema·의미 검증을 통과합니다.
협의안은 아직 초안이므로, 아래 1번의 "협의안대로 구현"도 정빈님이 초안을 확인하면 합의로 봅니다.

## 1. 정해 주셔야 할 것

| # | 항목 | 협의안 내용 | 지금 구현 | 필요한 답 |
|---|---|---|---|---|
| 1 | 수신 서버 | 10장 `POST /v2/world/snapshots`, 202/409/422 제안 | 규칙은 참조 구현(`worldmodel/contract/receiver.py`)으로 테스트. 실제 HTTP 전송은 없음 | 서버 주소, 인증 방식, 테스트 가능 시점 |
| 2 | 세션 등록·reset | 10장 새 세션은 명시적 reset 먼저. reset은 중앙의 대기 명령·질문·시연 이력도 초기화. 13장 등록 방법과 권한은 합의 대상 | World Model을 켤 때마다 새 세션 ID | 호출 방법과 권한. 시연 중 World Model만 재시작해도 reset할지, 세션을 이어 갈 방법이 필요한지 |
| 3 | 기기 명령·결과 | 10장 결과는 어댑터 → World Model → 중앙. 13장 지원 목록, 상태 문자열, endpoint, 변환 책임은 합의 대상 | 기기 상태 반영만 구현. 결과를 중앙에 전달하는 부분은 없음 | 중앙이 명령을 보내는 곳, 결과 이벤트를 받을 endpoint, 시연 어댑터로 앱의 `DeviceSimulator`를 쓸지 |
| 4 | 추적이 끊긴 사람 (HELD) | 5장·13장 신원 이어받기 기준은 함께 확인. 11장 추적 소실을 빈방으로 바꾸지 않음 | 방이 끊김 없이 OCCUPIED면 그 방에 유지. `world_inference`, `stale`, 자세 UNKNOWN, 좌표 null, 활동 `confirmed=false`. 방이 EMPTY/UNKNOWN이 된 적 있으면 `room_id=null` | 이 기준으로 괜찮은지 |
| 5 | 별첨 파일·PDF 위치 | 11장 `WorldSnapshot_2_0.schema.json`, `WorldSnapshot_2_0_example.json` | 받은 폴더에 없어 `worldmodel/contract/`에 직접 만듦. PDF는 eyear-orchestrator에 커밋되어 있지 않음 | 별첨 원본 공유 또는 이 파일을 기준으로 쓸지, PDF 커밋 |

## 2. 공유하는 값 (10장·13장: 설정으로 관리해 양쪽 공유)

| 항목 | 값 |
|---|---|
| Node 메시지 만료 | 3초 |
| 기기 상태 만료 | 10초 |
| 환경값 만료 | 120초 |
| 활동 `confirmed` 기준 | 같은 활동 3초 유지 |
| 끊긴 구성원 기억 | 30분 |
| keepalive | 변화가 없어도 30초마다 발행 |

## 3. 협의안대로 구현한 것 (답 불필요)

- 관측 만료: 새 메시지가 없어도 World Model이 감지해 stale/UNKNOWN을 발행 (10장)
- 발행 주기: 최대 초당 1회 + 의미 변화 즉시 (10장)
- `stable_for_s`: World Model이 이번 세션에서 본 이력으로 계산, 이력이 없으면 null (4장·5장)
- 풍향 대상: 현재 `people`만 참조, 없으면 null. 조작 전 대상 위치 확인 (6장·7장)
