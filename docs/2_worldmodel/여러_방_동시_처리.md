# 여러 방 Node 메시지를 동시에 받기 (NodeHub)

코드: [`worldmodel/hub.py`](../../worldmodel/hub.py) · 테스트: [`tests/test_hub.py`](../../tests/test_hub.py)

## 문제

Node 4대가 각자 1초마다 메시지를 보낸다. MQTT는 이 메시지들을 아무 스레드에서 아무 순서로 넘겨준다.
그런데 엔진은 집 전체 상태 **하나**를 들고 있다 (사람은 방을 오가므로 방별로 쪼갤 수 없다).
여러 스레드가 동시에 엔진을 건드리면 상태가 깨진다.

## 구조: 방마다 줄, 엔진은 한 번에 하나

```
 MQTT 콜백 ─ submit() ─┬─▶ [방1 줄]   ─ 해석 ─┐
  (받은 시각 즉시 기록) ├─▶ [거실 줄]  ─ 해석 ─┼─▶ 엔진 (잠금, 하나씩) ──▶ 0.2초마다 poll()
                       ├─▶ [방2 줄]   ─ 해석 ─┤                               │
                       └─▶ [세탁실 줄] ─ 해석 ─┘                    스냅샷 ─▶ 보낼 칸(최신 1장) ─▶ 정빈
```

| 규칙 | 이유 |
|---|---|
| 받은 시각은 **줄에 넣는 순간** 찍는다 | 줄에서 기다린 시간 때문에 오래된 관측이 최신처럼 보이면 안 됨 |
| 방(Node)마다 **줄이 따로** | 한 Node가 깨진 메시지를 쏟아내도 다른 방은 영향 없음 |
| 같은 Node 안에서는 **도착 순서 유지** | seq 역순 판단이 의미 있으려면 |
| JSON 해석·형식 검사는 줄마다, **엔진 반영만 하나씩** | 엔진 상태 보호 |
| 줄이 차면 **가장 오래된 것을 버림** (기본 20개) | Node 메시지는 매번 방 전체 상태라 최신이 옛것을 대신함 |
| 발행은 **0.2초마다 묶어서** | 동시에 온 방 메시지 4개가 스냅샷 4장이 아니라 1장으로 |
| 보내기가 느리면 **최신 1장만** 보냄 | revision이 계속 오르므로 중간을 건너뛰어도 수신측은 202 |
| 보내기 실패해도 엔진은 계속 | 정빈 서버가 잠깐 죽어도 집 상태는 계속 갱신 |

## 걸러내는 것 (방별로 셈)

`hub.stats()`로 방마다 볼 수 있다.

| 이름 | 뜻 |
|---|---|
| `accepted` / `restart` | 반영함 / Node 재시작으로 보고 반영 |
| `duplicate` / `out_of_order` | 같은 event_id / 옛 seq |
| `invalid` | JSON 깨짐, Node 0.1 형식 아님 |
| `topic_mismatch` | 토픽은 거실인데 메시지 안은 방1 |
| `room_mismatch` / `unknown_node` | 설정과 다른 Node |
| `overflow` | 줄이 가득 차서 버림 |
| `unrouted` (전체) | 토픽 형식이 이상하거나 Node 없는 방 |

## 쓰는 법

```python
hub = NodeHub(engine, sink=send_to_orchestrator)   # sink: 스냅샷 1장을 받는 함수
hub.start()                                        # 방별 스레드 + 발행 + 보내기 스레드
mqtt_client.on_message = lambda c, u, m: hub.submit(m.topic, m.payload)
...
hub.stop()                                         # 남은 메시지까지 처리하고 멈춤
```

테스트·replay에서는 스레드 없이 `hub.submit(...)` → `hub.pump()` → `hub.tick(now)`.
